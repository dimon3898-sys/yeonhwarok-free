# Studio cold start: additive validation candidate

This directory connects the restored Studio to a **new container's first
startup**. It does not replace a running service, build an image, render a
video, or operate a gCube workload. The existing renderer, authentication,
controller, mobile UI and runtime manifests remain unchanged.

Base repository commit:
`624b540cad6dcfbe44e7e5d98c2b3d2ae8694851`

Original image (digest pin, no image modification):
`ghcr.io/dimon3898-sys/world-simulation-shorts-engine@sha256:8ef393d3ed96db57f4b82b3c092c0393e7c1a2d8cdf01c88d8f56b9d24eba5da`

## Process contract

Tini is PID 1, with process-group forwarding enabled. Root `bootstrap.py`
validates the new source manifest and the existing runtime contract, then
uses the original `https_bootstrap.supervise()` function. Its spawn adapter
replaces only the expected old Studio child command with `worker.py`.
The existing GPU admission child remains under the original supervisor.

The new Studio runs as UID/GID 1000. The worker requires its root parent's
inherited pipe proof, matching process identity, pinned source files and
the existing configuration checks before calling the unchanged
`serve.application()` and instantiating `NvidiaPresentationController`.
Neither constructing this controller nor running the CPU suite requests a
GPU or rendering job. The original supervisor handles child cleanup and
container exit. A Studio exit terminates the container; it is not restarted.

## Startup inputs

Provision the restored baseline repository and these additive files at a
canonical, immutable path before starting the container. Source files and
their parent directories must not be writable by UID/GID 1000. The source
mount is read-only in the CPU suite. Preserve the original image digest.

The provider must support replacing the **container entrypoint**, not just
passing arguments to the image's old entrypoint. The required argument
vector is:

```text
/usr/bin/tini -g -- /usr/bin/python3 -I -B <startup-dir>/bootstrap.py
  --startup-manifest <startup-dir>/STARTUP_MANIFEST.json
  --startup-manifest-sha256 2d2a9244e0bb7a1745e1ecc3e8e5f11b670b00f0660b85f78aa10087a5fd32fa
  --source-manifest <repo>/world-simulation-shorts-engine/recovery/codex-to-gcube-handoff-v1/RUNTIME_SOURCE_MANIFEST.json
  --source-manifest-sha256 138f5ff4761e2fa3589e15493ded5401afe1ec4dfa0dc5ad5a725e03e53b9270
  --export-root /world-storage
```

`<startup-dir>` is `<repo>/world-simulation-shorts-engine/recovery/studio-cold-start-v1`.
The argument vector is a configuration contract, not a command to run inside
an already running workload.

Supply the existing supported environment inputs through a private provider
input mechanism: `WORLD_ENGINE_STUDIO_OWNER_CODE`,
`WORLD_ENGINE_STUDIO_OPERATOR_POLICY_JSON`,
`WORLD_ENGINE_STUDIO_PUBLIC_ORIGIN`, and `WORLD_ENGINE_STUDIO_STATE_ROOT`.
The policy and origin use the unchanged validators. An actual operator's
owner code, policy or origin is never generated by this connector.
Set `GPU_BACKEND=vulkan` and `WORLD_ENGINE_UNIVERSAL_IMAGE_DIGEST` to the
digest above; the Studio port remains 8080. Port 8000 is reserved for the
existing GPU admission service.

The private state root must be a **new, nonexistent directory** whose parent
exists. It must be outside `/world-storage` and disjoint from the export
root. Existing authentication directories are rejected, not rotated or
overwritten. The export root must already exist. Establish approved private
persistence and a new export/cache allocation before production use; this
candidate does not establish Dropbox persistence or change any backup.

The root startup marker in `/run/world-engine-cold-start` allows only one
startup attempt in that container. A failed attempt is not retried.

## CPU validation and limits

The dedicated workflow is restricted to
`validation/world-engine-studio-startup-20261025`, runs on standard
`ubuntu-24.04`, and refuses execution when `github.run_attempt != 1`.
There is no manual, schedule, GPU, image-build, deployment or rendering
trigger. The original image is pulled once and used directly, with
disposable CPU-only Docker containers and synthetic, short-lived test
authentication. Test inputs and state are not production configuration.

The suite tests real process startup, the latest controller and existing
aviation Scene connection, duplicate-start prevention, TERM/INT forwarding,
child exit and cleanup, port conflicts, and existing-private-state refusal.
It does not call rendering, GPU-preflight or deployment endpoints. The
containers and temporary authentication files are removed after the suite.
Only sanitized results are logged.

Run the suite once in the approved standard CPU runner:

```text
python3 world-simulation-shorts-engine/recovery/studio-cold-start-v1/tests/container_suite.py --repo <checkout> --image <pinned-image>
```

This README is a candidate specification, **not evidence of a passed run**.
`STUDIO_STARTUP_FIXED` requires an actual successful CPU container suite
and GitHub read-back SHA-256 verification of every added file. Record the
exact commit, Actions run, attempt and results separately. Never rerun a
failed workflow or weaken a test to claim success.

A CPU PASS does not establish NVIDIA/Vulkan rendering, a real HTTPS route,
provider entrypoint support, production authentication, durable storage,
cost control, or a completed 6-second MP4. Those remain deployment gates.
