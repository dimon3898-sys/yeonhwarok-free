## 0. 이번 작업을 한 문장으로 고정

“국가 문맥 제시 → 넓은 지도 → 두 장소 선택 → 두 지명 공개 → 핵심 장소의 큰 핀 → 그 핀을 기준으로 깊은 확대 → 실제 형상의 경계선 공개 → 수치 공개 → 확대 구도 유지”를 기존 WORLD ENGINE에 재사용 가능한 연출 프로필로 연결하라.

이번에는 항공망·무역망·가상 전쟁을 다시 세 개 만드는 작업이 아니다. 자유 자연어, 역사 DB, 새 주제 수를 늘리는 작업도 아니다. 아래 한 가지 연출 문법의 화면 품질을 끝낸다. 특정 국가명이나 좌표를 엔진 코드에 하드코딩하지 않고 데이터 바인딩과 프리셋을 분리한다.

원본에 관찰되지 않은 항공기·배·군대·화살표·폭발·반복 레이더 펄스·숫자 카운트업·마지막 전체 지도 복귀를 임의로 추가하지 않는다. 원본의 지도 확대는 영토 확장이 아니다.

## 4. 카메라 — 구도, 이동, 축소, 확대, 회전

### 4.1 추상 지시 대신 화면 제약을 만족시켜라

첫 화면에서 주국가는 큰 피사체다. 줌아웃하는 동안 주국가는 화면 왼쪽 위 쪽으로 이동하면서 작아지고 주변 국가가 들어온다. f170 부근 가장 넓은 구도에서 접근 방향으로 바뀐다. 두 장소를 충분히 보여준 다음 작은 핵심 장소를 크게 확대한다. 끝에는 경계 설명을 위해 큰 핀을 왼쪽 위로 보내고 경계선을 수평에 가깝게 정렬한다.

숫자는 원본 화면 측정 근사다. `widthFraction`은 지형의 화면상 너비이지 국가 실제 면적 비율이 아니다.

### 4.2 계산과 보간 규칙

- 입력된 실제 geometry/anchor를 사용해 위 screen constraints를 만족하는 카메라 경로를 생성한다.
- 지리 형상을 늘이거나 경계 정점을 옮겨 화면 점유율을 맞추지 않는다.
- 중심은 C1 연속, scale은 log 공간의 bounded monotone cubic, 각도는 unwrap한 연속 경로를 기본으로 한다. 과도한 overshoot는 금지한다.
- 표의 각 행마다 속도를 0으로 만들지 않는다. 중간 제약점이지 정지 컷 목록이 아니다.
- 줌아웃→줌인 전환은 f170 전후의 유한한 감속/가속으로 처리한다.
- 실제 카메라 투영을 기준으로 맵·영역·경계선·앵커를 모두 같은 변환에 둔다. 핀과 지명은 투영된 위치에 붙되 화면에서 수직/읽기 방향을 유지한다.
- 피치/FOV/고도는 원본만으로 유일하게 역산되지 않는다. 기존 승인된 지도 투영을 재사용해 화면 제약을 맞춘다. ‘45° 궤도’, ‘우주에서 하강’ 같은 미관찰 연출을 더하지 않는다.
- 평면 지도 회전으로 충분하다면 3D 궤도 시스템을 새로 만들지 않는다. 지형이 아닌 합성 완료 영상만 회전시키는 오프라인 효과로 대체하지 않는다.
- 프레임 f만 주어져도 동일 결과가 나오게 한다. 누적 deltaTime, wall clock, 이전 draw 호출 수에 의존하지 않는다.
- 수치가 해당 데이터 geometry와 함께 동시에 만족되지 않으면 원인·잔차를 보고한다. 카메라/데이터 중 무엇이 부족한지 구분하고 임의 변형으로 맞추지 않는다.


### 4.3 평면/2.5D 기반 구현 시의 구체적 프레이밍 계산

아래는 새 월드 좌표를 발명하는 방식이 아니라 기존 검증된 지도 투영 Q(p)를 사용하는 화면 맞춤 공식이다. 엔진의 실제 카메라/scene 변환으로 구현하고 현재 factory.screen 결과와 일치하는지 검사한다.

screen(p) = s × R(θ) × [Q(p) − Q(pivot)] + targetPixel.

- targetPixel=(1080u,1920v). 큰 핀의 pivot은 제공된 핵심 지리 anchor다.
- scale s는 실제 polygon을 투영한 bbox의 화면 점유율 목표로 계산한다. geometry 자체에 s를 곱해 데이터를 수정하지 않는다.
- 두 점 장면에서는 dWorld=Q(B)−Q(A), dScreen=targetB−targetA를 이용해 s=|dScreen|/|dWorld|, θ=atan2(dScreen.y,dScreen.x)−atan2(dWorld.y,dWorld.x)로 초기 해를 잡는다. 두 핀 거리와 방향, safe 영역, 실제 source 범위를 함께 재검증한다.
- 경계 장면의 θ는 원하는 화면 경계각에서 Q(boundaryEnd)−Q(boundaryStart)의 각을 뺀 값으로 초기화한다. 곡선이면 metric 지점의 제공된 접선/설명 선분을 사용한다.
- 비평면/원근 카메라에서는 위 식을 맹목적으로 적용하지 말고 기존 실제 project 함수로 같은 화면 잔차를 최소화한다. pitch/FOV를 임의로 사실처럼 고정하지 않는다.
- source envelope는 회전된 뷰포트의 네 모서리를 역투영해 계산한다. 회전 전의 axis-aligned bounds만 검사해서 검정 모서리/소스 틈을 만들면 FAIL.
- 핀은 마지막 screen 위치에 screen-pixel 그래픽으로 올리고, 지명은 screen-upright, 경계와 영역은 지리 투영을 유지한다.

## 5. 핀 — 모양, 크기, 팝인, 지리 앵커

원본의 마커는 노란 물방울형 지도 핀이고 가운데 원형 구멍으로 지도가 보인다. 단순 점·항공기·화살표로 바꾸지 않는다.

출력 1080×1920에서 다음을 AUTHORING 기본값으로 고정한다.
작은 위치 핀: 49×64px, 원형 구멍 지름29px.
큰 핵심 핀: 116×151px, 원형 구멍 지름68px.
색 #FEE901, 아주 얇은 1.5px 외곽선, 필요시 낮은 명도의 최소 그림자. 반복 발광 링은 없다.
앵커는 바운딩 박스 중심이 아니라 맨 아래 끝점이다. 핀의 구멍을 불투명 배경색으로 메우지 않는다.
지도 확대에 따라 핀 크기가 커지지 않는다. SCREEN_PIXELS 크기, SCREEN_UPRIGHT 방향이다.


핀 외곽의 authored 벡터 형상(원작 SVG를 추출한 것이 아님):
viewBox="0 0 116 151"
outerPath="M58 151 C45 132 0 96 0 58 C0 26 26 0 58 0 C90 0 116 26 116 58 C116 96 71 132 58 151 Z"
원형 투명 구멍: 중심(58,56), 반경34. fill-rule=evenodd 또는 동등한 투명 hole geometry.
끝점은(58,151). 작은 핀의 외곽은49×64로 맞추고 구멍 지름은29px로 따로 고정한다.
기존 핀 모듈이 동등한 형상을 제공하면 재사용하고, 아니면 이 새 프로필 전용 style/asset 변형으로 연결한다. 보호된 기본 핀을 전역 교체하지 않는다.

작은 핀의 1회 팝인 창: 원본 [177,193). 정확한 매프레임 크기는 원본에서 불확실하므로 아래 큰 핀의 일회성 팝인 곡선을 16프레임에 리샘플하여 쓴다. ‘관측된 원작 곡선’으로 표시하지 않는다. 최종 크기 이후에는 화면 밖으로 나갈 때까지 유지한다.

큰 핀 팝인: 원본333에서 시작. 아래 값은 관측 크기에서 근사한 이번 명세값이다.
f333 0.000,334 .113,335 .278,336 .461,337 .687,338 .957,
339 .922,340 .861,341 .843,342 .870,343 .939,344 .991,
345 .983,346 1.000,347 1.000.
f348~574는 scale1을 유지한다. 한 번 커진 뒤 조금 움츠러들며 안정되는 모양이다. 매초 펄스를 반복하지 않는다.

핀이 나타나는 동안 카메라 이동은 멈추지 않는다. 원본333~350에서 팝인과 접근 시작이 겹친다.

## 6. 지명 — 두 장소를 따로 읽게 만들어라

예시 원본 문구 A=세우타, B=멜리야. 실제 생성기는 사용자 제공 location.label을 사용한다. 이 두 문자열을 엔진에 하드코딩하지 않는다.

48px, weight700, 흰색 #FFFFFF. 푸른 후광 #182BCB, radius16px, opacity .65. 원작 폰트는 확인되지 않았으므로 프로젝트에서 사용 가능한 한국어 폰트를 선택하고 자산명·라이선스를 기록한다. 글리프 누락·네모 상자는 FAIL.

핀 상단에서12px 위에 텍스트의 하단이 오게 한다. 텍스트 기준은 전체 단어를 완성했을 때의 중앙 정렬이다. 글자가 하나씩 생길 때 이미 나온 글자를 계속 좌우로 밀지 않는다. 글자는 화면에서 수직으로 읽힌다.

A 글자 등장: f289 ‘세’, f293 ‘우’, f297 ‘타’.
B 글자 등장: f311 ‘멜’, f315 ‘리’, f319 ‘야’.
각 grapheme은 4프레임 동안 scale0→1, opacity0→1의 ease-out으로 정착한다. 한글 자모/UTF16 코드유닛을 분리하지 않고 grapheme cluster 단위로 처리한다. 글자 간4프레임 간격이 기준이다. 다른 이름 길이는 같은 간격을 적용하되 다음 사건 전 읽기 유지 시간이 부족하면 자동으로 다음 사건을 밀지 말고 명시적 연출 길이 검증 결과를 반환한다.

첫 이름은 둘째 이름이 나올 때도 유지한다. f333의 큰 핀이 등장했다고 두 기존 이름을 즉시 삭제하지 않는다. 카메라 접근으로 위치가 화면 밖으로 나갈 때 자연스럽게 cull한다. 원본에서는 약f360~364에 주변 이름/핀들이 벗어나는 것이 관찰된다.

실제 글리프 bbox로 충돌과 safe 여부를 검사한다. '이름은 metadata에 있다'는 것으로 화면 라벨 구현을 통과시키지 않는다.

## 7. 영역과 지도 재질 — 지리 형상을 움직이지 마라

주국가/국소 영역: #E3B500 alpha.55, 외곽선 #FFF4C8 3px, halo10px opacity.28.
문맥 지역: #27BED4 alpha.42, outline2px.
위 값은 구현 기본값이며 원작 셰이더의 정확한 RGBA 역추출이 아니다. 지표 질감과 해안선이 채색 아래에서 보여야 한다.

- 주국가 색은 줌아웃 중 계속 유지된다.
- 청록 문맥 영역은 [202,240)에서 opacity를 공개하도록 지정한다. 좌표/형상은 그대로다. 실제 화면의 첫 색 변화는203~204 부근으로 관측된다.
- 작은 해안 영역은 실제 제공된 정밀 폴리곤을 사용한다. 단순 bbox 사각형을 정답처럼 쓰지 않는다.
- 단, 사용자가 사각형 가상 영역을 제공한 별도 fixture는 사각형으로 보이는 것이 데이터 오류는 아니다. 이를 실제 지리 형상의 재현 PASS로 오인하지 않는다.
- 카메라가 확대되어 큰 나라나 문맥 채색이 화면 밖으로 나가는 것은 정상이다. 클리핑 때문에 지리 geometry를 새 경계로 바꾸지 않는다.
- 거친 저해상도 해안 geometry를 부드럽게 보이게 임의 스무딩하지 않는다. 데이터 정밀도 부족은 DATA_DETAIL_BLOCKED로 분리한다.
- 소스 경계/재질 이음선, 사각형 텍스처 전환, 과도한 블러·업샘플링으로 세부 지형이 있는 것처럼 만들기 금지.


넓은 구도의 주변 국경은 실제 경계선 geometry를 사용한다. 원본에서는 유럽 쪽 흰색과 아프리카 쪽 노란색 그룹이 보인다. 새 프로필 기본값은 style group A=#F3F4E9/2.5px, group B=#D9CF24/2.5px이며, 데이터의 style-group binding으로 선택한다. 대륙명 조건문을 엔진에 넣지 않는다. 국경 선 두께도 화면 px 기준이며 확대할수록 두꺼워지게 하지 않는다.

## 8. 사건 — 경계선이 먼저, 수치는 그다음

여기서 사건은 전투 발생이 아니라 새로운 지리 정보를 공개하는 편집 사건이다.

### 8.1 경계선

제공된 detailBoundaryGeometryId의 LineString을 사용한다. 올바른 지리 시작/끝점과 순서가 필요하다. 화면에서는 아래-왼쪽에서 위-오른쪽으로 드러나는 방향이다.
원본 f455: reveal=0, f485: reveal=1.
reveal(f)=clamp((f−455)/30,0,1). 원본의 정확한 내부 easing은 알 수 없으며 이 식은 구현 기준이다.

Reveal을 화면 길이로 재계산하지 않는다. 지도 확대/회전과 독립적인 원본 선의 arclength 순서로 잘라 현재 투영에 렌더링한다. 카메라 때문에 전체 선이 길어져도 진행이 거꾸로 돌아가거나 속도가 튀지 않아야 한다.

스타일: 노란 core6px #FFF000, halo radius24px #FFE000 opacity.55.
이것은 선 전체가 일정 강도로 번쩍이는 반복 펄스가 아니다. 새로 공개된 부분은 남아 있고, 완료 후 f574까지 경계선 전체를 유지한다.
선 끝에 큰 점·화살표·폭발을 추가하지 않는다. 영상의 85m 설명 구간과 무관한 전선을 생성하지 않는다.

### 8.2 수치 텍스트

원본에 보이는 값은 ‘85 m’다. 이는 원본 영상 내용의 관찰이며 지리적 사실을 독립 검증한 결과가 아니다. 값/단위는 제공된 metricValueId를 사용해야 한다. 원본 텍스트만으로 실제 측량값의 정확성이 인증된 것처럼 표시하지 않는다.

f487 ‘8’, f492 ‘5’, f497 ‘m’의 5프레임 간격 공개.
공백은 layout 간격이지 별도 팝인 글리프가 아니다. 각 글리프는8프레임에 걸쳐 scale0→1, opacity0→1로 정착하여 f505까지 완전히 읽히게 한다.
다른 수치에서는 숫자를 0부터 증가시키지 않고 제공 문자열 자체를 grapheme reveal한다. 자리 수가 달라지면 명시적 이벤트 길이를 검증한다.

52px weight700 흰색, shadow2px. 선의 지리 arclength 중점을 투영한 위치를 기준으로 선에서24px 떨어져 붙인다. 기본 선의 위쪽 법선을 선택하고 갑자기 다른 쪽으로 뒤집지 않는다. 글자 baseline은 선의 화면 방향을 따르되 언제나 읽는 방향을 유지한다. 수직/수평 주변의 각도 뒤집힘을 방지한다.

f505~574의70프레임(2.333초) 동안 전체 수치를 읽을 수 있게 유지한다. 이때 지도는 완전히 멈추지 않고 회전/확대가 감속한다. 마지막 전체 지도로 줌아웃하는 연출은 금지한다.

## 9. 현재 코드에서 실제로 확인한 연결 장벽

아래는 82854af에서 읽은 내용이다. 시작할 때 실제 함수·라인을 재확인하고 변경명세에 남긴다. 막연히 ‘더 역동적으로’ 바꾸지 말고 정확히 이 장벽과 위 화면 목표를 연결한다.

### 9.1 presentation_plan.mjs

경로: recovery/universal-presentation-v2/presentation_plan.mjs
- validatePresentation: KEYFRAMES는 frame/center/zoom만 허용한다.
- PRESENTATION_FINAL_ENDPOINT_CLOSEST_REQUIRED: 마지막 keyframe이 가장 가까운 구도여야 한다.
- ROUTE_FOLLOW는 상수 zoom이다. 이번 작업은 항로 추적이 아니므로 route-follow 개발은 범위 밖이다.
- compilePresentationCameraPlan: 기존 reference_camera_adapter_v1 / Camera V5에 bounds 기반 트랙을 전달한다.
- 실제 현재 카메라와 기존 고정 분석 카메라를 구분한다.

조치: 기존 V2 계약을 조용히 바꾸지 말고 opt-in reference director sidecar를 만든다. 회전과 screen-subject framing을 명시적으로 지원하고 기존 호출은 그대로 동작하게 한다. 전역 트랙에서 짧은 검수 창을 선택한다. A 창의 끝이 넓은 구도라는 이유로 가짜 마지막 줌인 keyframe을 끼워 넣지 않는다. 전체 트랙의 가장 가까운 뷰/소스 한계를 검사한 뒤 창을 잘라 평가하거나, 별도 계약으로 동등한 한계 검사를 수행한다. 기존 검증기를 그냥 삭제하지 않는다.

### 9.2 presentation_runtime.mjs

경로: recovery/universal-presentation-v2/presentation_runtime.mjs
- factory.updateCamera(bounds)로 현재 뷰를 갱신한다.
- factory.renderFrame의 graphics/boundaries/glow/dem이 false이고, location/country/title 등의 reveal이0인 경로다.
- 최종 graphics.draw는 marker만1, location/country/title/disclosure는0으로 호출된다.
- markersAt에서 모든 마커 bbox를 safe에 강제한다.
- UP2_AREA_SOURCE_FOOTPRINT_OUTSIDE_SAFE는 표시 영역의 모든 정점을 safe 안에 요구한다.
- 엔진 소비자는 EXISTING_AREA_V3와 EXISTING_FLOW_V2만 허용한다.

조치:
A. 검증된 기존 glyph/label/layout/graphic 모듈을 재사용해 실제 지명·수치 텍스트 패스를 연결한다. 보호된 고정 atlas를 덮어쓰지 않고 새 프로필 전용 atlas/측정 결과를 생성한다. 글자가 실제 프레임에 그려졌는지 검증한다.
B. 기존 Event V1의 geographic line/metric 기능 및 공개 소비 경로를 감사해 위 경계 공개에 연결한다. GENERAL 지리 설명을 가짜 WAR 이벤트로 바꾸지 않는다. 부족한 계약만 버전이 있는 별도 presentation event binding으로 추가한다.
C. 마커/영역 안전 규칙을 아래 3개 역할로 분리한다.
   1) REQUIRED_VISIBLE_SAFE: 현재 설명 중인 큰 핀, 현재 읽어야 하는 지명/수치. 보호 여백 포함해 safe에 있어야 한다.
   2) CONTEXT_CULL: 이전 문맥의 작은 핀/이름. 화면 밖으로 자연스럽게 나가면 cull. 다음 등장과 혼동되는 재팝인 금지.
   3) AREA_VIEWPORT_CLIP: 넓은 국가/문맥 영역. viewport에서 clip하지만 원본 geometry/hash는 유지. safe 안에 모든 꼭짓점을 강제하지 않는다.
D. 이전 두 지명을 읽는 f289~332에는 REQUIRED_VISIBLE_SAFE, 핵심 핀으로 이동하는 f333 이후에는 CONTEXT_CULL처럼 역할의 시간 범위를 명시한다. 전체 검사를 비활성화하는 방식은 금지한다.
E. 회전되는 지도와 선/영역/핀의 지리 투영은 동일해야 한다. 영상 합성 후 지형만 따로 회전시키지 않는다. 실제 projection/inverse projection과 source envelope 검증을 함께 업데이트한다.
F. 기존 fixed-model Event/Flow 시간 평가를 실제 moving-camera admission으로 위장하지 않는다. 현재 frame의 투영·bbox·source 검사 결과를 별도로 남긴다. cameraLocked/settle 상태를 거짓으로 고정하지 않는다.

### 9.3 기존 소스/화질 제한

REGION_SOURCE_CATALOG 및 source receipt를 확인한다. 전역 NE1 원본이 LFS 포인터뿐인 상태를 실제 래스터가 있는 것으로 처리하지 않는다. 기존 regional NE1/global RGB의 해상도와 커버리지로 국소 경계까지 충분히 확대할 수 있는지 별도 검사한다.

같은 소스를 확대하는 동안 갑자기 다른 재질로 바뀌면 FAIL. 높은 세부 원본으로 바꿀 필요가 있다면 동일한 지리 정합·저작권·좌표계·스타일 전이 증거를 제출하고 재질 이음선이 없어야 한다. 새로 없는 DEM/수심/위성 세부를 AI나 노이즈로 만들어 사실적인 원자료라고 주장하지 않는다.

### 9.4 보호 파일과 확장 가능성

가능한 한 추가 모듈/기존 공개 훅으로 구현한다. 단, 기존 렌더러가 bounds 갱신만 노출하며 필요한 회전·label/Event 소비 훅도 보호 파일 수정 없이는 전혀 쓸 수 없다면, 정확한 파일·함수·필요한 최소 변경을 CAPABILITY_EXTENSION_REQUIRED로 제출한다. 보호 파일을 몰래 수정하거나 별도 가짜 렌더러로 검수를 우회하지 않는다.

## 10. 데이터 준비와 표현 검증의 분리

dataBindings의 null은 의도된 미바인딩 상태다. 최종 입력으로 렌더링할 수 없다.
필수 데이터:
1) 주국가 geometry + 문맥 국가 경계.
2) 두 위치의 정확한 anchor/표시명.
3) 작은 핵심 장소 anchor + 충분한 정밀도의 폴리곤.
4) 실제 설명할 LineString과 시작/끝 방향.
5) 표시할 값·단위·근거 상태.
6) 전 카메라 범위를 덮는 사용 가능한 지도 소스/원본 해시/라이선스/해상도.

우선 이전 프로젝트 자료와 검증된 source registry에서 실제 파일을 재사용한다. 새 역사 DB 구축을 시작하지 않는다. 제공된 값과 출처가 충분하면 바인딩하고, 없으면 정확한 누락 ID와 필요한 형식을 NEEDS_INPUT으로 보고한다. 단순 사실 설명만으로 지리 폴리곤이 생긴 것으로 간주하지 않는다.

누락이 있어도 독립적인 단위 테스트와 명시적 가상 geometry로 연출 기능 자체를 검증할 수 있다. 하지만 이를 같은 지리 재현 PASS로 승격하면 안 된다. 임의 해안 형상이나 스크린샷 따라 그린 윤곽은 실측 경계가 아니다.

판정은 분리한다:
- DIRECTOR_IMPLEMENTATION: 기능/코드/실제 draw.
- GEO_AND_SOURCE_READY: 해당 원본 지리·소스 충족.
- REFERENCE_VISUAL_MATCH: 해당 참조에 대한 화면 비교.
- HISTORICAL_G3: 이번 작업으로 자동 해제되지 않는다.

자료가 없을 때 무엇이 missing인지 이미 설명된 범위 내에서 찾고 기록한다. 추측을 승인 요청 없이 사실 데이터로 채우거나 차단을 없애기 위해 historical을 fictional로 바꾸지 않는다.

## 11. 실제 실행 순서와 실패 게이트

PHASE A / READ-ONLY BASELINE
전체 SHA/브랜치/보호 manifest, 원본635프레임 및 첨부 명세 일치를 확인한다. 위 기존 코드 연결 지점을 파일:함수:라인으로 재확인한다. 없는 기능과 연결이 끊긴 기능을 구분한다. 이전 503개 테스트와307개 보호파일의 실제 목록을 확보한다.

PHASE B / BOUNDED DIRECTOR IMPLEMENTATION
카메라 프레이밍/회전, 두 크기의 핀, grapheme 라벨, geographic boundary reveal, metric label, 역할별 visibility만 구현한다. 기존 코드가 있으면 재사용한다. 새 실행 경로도 실제 Studio 인증→검증→worker→렌더러→인코더로 연결해야 한다. 별도 Canvas 영상 파일을 최종 Studio 출력으로 가장하지 않는다.

PHASE C / DATA AND PRE-RENDER GATES
소스와 geometry 바인딩, 전체 전역 카메라 envelope, 최종 확대 해상도, 글리프/레이아웃, 전역 f29..574 상태를 점검한다. f30/170/270/332/350/390/420/455/485/505/540/574를 실제 draw한다. 정적 프레임에서 구조적으로 실패하면 영상부터 만들지 않는다.

PHASE D / FREE STUDIO REVIEW WINDOWS
통과 시 A180 + B180 + C186프레임만 실제 Studio 무료 CPU로 제작한다. 기존 240프레임 한도를 전체 길이를 거짓으로 신고하거나 검증기를 끄는 방식으로 넘지 않는다. 세 작업이 전역 일정의 선택 창을 렌더링할 수 있게 정직한 request/window 계약을 만들고 local range와 global time을 각각 검증한다. 각 작업은240이하, 총546프레임이다. 전체18.2초를 한 요청으로 렌더링했다고 허위 보고하지 않는다. 자동80초 제작/추가 주제 장편은 금지한다.

PHASE E / ACTUAL PIXEL AUDIT
세 MP4 전체 디코딩, 프레임/PTS/검정/손상/연속성 검사. 비교 키프레임과 전 프레임 접촉 시트, 실제 화면 bbox/픽셀 mask, 시간별 선/글자/마커 상태를 제출한다. 소프트웨어 출력 기준이며 실물 Android/NVIDIA 테스트로 확대 해석하지 않는다.

필수 게이트 실패 시 종속 후속 제작은 중단한다. 독립적 분석/단위 테스트는 진행 가능하되 실행하지 않은 결과를 PASS로 채우지 않는다. 실패 항목이 이번 제한 범위 밖이면 새 주제를 추가하지 말고 BLOCKED 범위만 정확히 보고한다.

## 12. 합격 기준 — metadata가 아닌 실제 영상

A. 원본/데이터 무결성
- 기존503개 검사 실제 재실행 결과 및 새로운 검사 개수를 별도 보고. skip으로 개수 맞추기 금지.
- 보호307개 hash 일치, 기존 FINAL/캐시/Asset 불변.
- 모든 rendered geometry/값에 input ID와 source hash 추적 존재.
- 연출 ON/OFF 및 기존 V2 경로의 회귀 검증. 새 프로필 OFF에서 기존 출력을 바꾸지 않는다.

B. 카메라/화면 측정
- 같은 지리 입력으로 비교할 때 키프레임 앵커 좌표의 허용오차는 u,v 각각.02.
- 주국가/국소 대상 화면 bbox 비율 허용오차 .04.
- 실제 경계선 방향 허용오차3°. 이것은 카메라 yaw 비교가 아니라 화면 선분 비교다.
- 프레임 로그의 ‘cameraChanged=true’ 또는 변한 pixel1개만으로 통과 금지.
- 지도 지형/해안 고정점과 주대상 크기를 직접 비교해 큰 줌아웃과 깊은 줌인을 확인한다.
- 원본 뒤쪽처럼 움직임이 감속되어야 한다. 표의 각 샘플에서 정지하거나 순간 점프하지 않아야 한다.
- 다른 geometry fixture에서는 이 원본 숫자와 정확히 같을 필요는 없지만 동일한 역할/화면 문법과 설정값으로 작동해야 한다. 본 참조의 시각 재현 PASS와 혼합하지 않는다.

C. 핀/글자/선
- 팝인 종료 후 큰 핀의 크기는 기준 대비±3% 이내. 지도 확대율만큼 커지는 핀은 FAIL.
- 지리 앵커 투영점과 핀의 아래 끝점 잔차는2px 이내.
- 이벤트 등장 프레임은 목표±2프레임 이내.
- 두 지명은 실제 표시되고 글자 순서가 맞아야 한다. 포인트나 metadata로 대체 불가.
- 완성 metric은 f505~574 최소70프레임 읽을 수 있어야 한다.
- 완료 경계선이 지워졌다 다시 생기거나 reveal이 역행하지 않아야 한다.
- 현재 필수 설명 대상의 충돌/화면 이탈 금지. 이전 문맥이 화면 밖으로 나가는 것은 FAIL이 아니다.
- 전체 라벨이 projection 변화와 무관하게 화면에 붙어 떠다니거나 회전축이 어긋나면 FAIL.

D. 실제 영상/소스
- A1080×1920/30fps/180, B180, C186, H264, 무음.
- f208→209와 f388→389에서 전역 카메라/지리/가시성/이벤트 상태가 연속이어야 한다. 두 연속 프레임이 완전히 같아야 한다는 뜻은 아니다. 같은 전역 트랙의 다음 sample이어야 한다.
- 텍스처 사각 이음선/과도한 확대 뭉개짐/글리프 누락/깜박임/누락 프레임 없음.
- 원본 휴대폰 UI 가림 부분은 픽셀 비교에서 제외한다. 새 영상에 원본 UI를 그려 SSIM을 올리지 않는다.
- 전체 이미지 SSIM만으로 평가하지 않는다. 지리 내용/재질 차이가 있을 수 있으므로 카메라·핀·글자·경계의 개별 측정과 사람의 읽기 쉬움 판정이 필요하다.

E. 범용성은 작은 검사로 종료
- 서로 다른 좌표/비사각형 polygon/라벨 길이를 가진 명시적 비역사 fixture 2개에서 같은 프리셋으로 실제 draw한다.
- 이는 국가명/좌표 하드코딩 방지 검사다. 새로운 주제3개의 전체 MP4 제작이나 자연어 엔진 확장으로 범위를 늘리지 않는다.

결과 상태:
- DIRECTOR_TECHNICAL_PASS + REFERENCE_QUALITY_REVIEW_REQUIRED: 구현/무료 영상/자동·프레임 검사가 끝났으나 사용자 시각 승인 대기.
- DATA_DETAIL_BLOCKED: 지리/정밀도/소스가 부족. 기술 완료 범위와 미완료 비교를 분리.
- CAPABILITY_EXTENSION_REQUIRED: 보호 파일 바깥 공개 훅만으로 필요한 동작을 구현할 수 없다는 증거와 최소 변경 요청.
- NEEDS_REWORK: 이번 한정된 연출 명세의 구현 또는 실제 화면이 실패.

503개 테스트 PASS, JSON 생성, 카메라 함수 존재만으로 reference 품질 PASS를 선언하지 않는다. ‘자연어를 더 지원하면 해결’이라고 다음 주제로 넘기지 않는다. 이번 완료 기준은 위 화면 순서와 수치가 실제 프레임으로 증명되는 것이다.

## 14. 실행 명령

첨부 원본의 hash와 문서를 확인하고 PHASE A부터 실제 수행하라. 단계가 통과하면 다음 단계로 진행한다. 가능한 기존 모듈을 재사용하며 이번 명세의 추가 연결만 구현한다. 단순 계획서 제출로 끝내지 않되 보호·비용·지리 사실 조건을 우회하지 않는다.

이 지시서를 작성한 채팅은 코드 수정·Codex 실행·유료 작업을 수행하지 않았다. 실행 결과는 코덱스가 실제 증거와 함께 새로 보고해야 한다.
