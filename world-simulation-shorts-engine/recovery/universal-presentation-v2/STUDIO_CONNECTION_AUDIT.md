# Studio presentation path audit

Baseline `b0d013832ee38571f9d3dfe685ce63f7083ba90f`; all previous namespaces remain immutable.

The previous data Studio is an authenticated, detached source-checkout path. `universal-data-pipeline-v1/studio_adapter.py` calls the preserved HTTP server and isolated original source manager. Its `_normal` is intentionally restricted to the old structured prompt and five region IDs. Its worker passes `--source-region` to the fixed-region capture. The job manager already owns explicit owner consent, idempotent claims, active-job rejection, safe private storage, detached process launch, bounded software execution and failure records. Those functions should be reused rather than replaced.

The previous actual Scene-key-order defect was already fixed: `sceneWireJSON` survives the canonical private JSON storage, with semantic and wire hashes checked separately. The new presentation path must preserve that behavior for every segment of its composite request. It must not sort and then reinterpret old Scene geometry records.

The new path therefore adds a versioned Studio request/controller and compiler/capture dispatch only. It reuses the original authenticated HTTP service and job manager. It explicitly selects either one qualified scene or a complete contiguous timeline; the latter cannot omit blocked scenes. Source qualification must complete before a claim is launched. A real CUT is a runtime switch between separately provided Scenes, not a label applied to a state change within one Scene.

No original Studio, renderer, FINAL, image, job claim or cache is changed by this audit. No GPU, deployment, paid API or rendered visual-quality result is claimed here.
