# Source front visibility above static country boundaries

The first eight-source image is preserved in
`checkpoints/PRE_VISIBILITY_FIX_IMAGE.json`. Its source bindings, geometry,
draw-call checks and image inventory passed, but those checks did not prove
visible historical-front pixels at every date. Root review of the actual last
PNG found the white source front was hidden near the static country border.

Read-only analysis of the unchanged native mask formula and actual projected
source bounds found all1,063 sampled last-front centerline points inside the
static-country-boundary mask. Their clearance exceeded the white core radius.
This is a CPU reconstruction, not an extra NVIDIA measurement. The actual image
is retained as the before evidence; a draw-call flag alone is not visual proof.

The additive V4 adapter now gives the **source-reviewed partial front** display
priority over a present-day country boundary, only while that source snapshot
is selected and occupation areas are empty. The existing public area-pass API
receives no static-country exclusion segments for that source-front draw. The
native boundary restoration still executes beforehand. All unchanged fallback
and schematic draws retain their original boundary segments.

This is a new source-composition rule. It does not alter an old renderer,
shader, frontier engine, API, style, camera, source coordinate or source date.
It does not offset geometry or create another decorative line. Only the actual
source stroke and its existing halo can cover a static boundary underneath it.
All-native-boundary-pixels-unchanged is therefore not claimed at source-active
frames; that earlier rule would erase the real historical line.

Marker, text, title, annotation reservations, viewport and safe area retain their
original protection. No unverified occupation fill or military unit is added.
The source profile and label still say approximate and partial. Country colors
underneath do not become evidence of historical occupation.

Before a new image is admitted, actual software A/B must select every source
snapshot and the final frame. The control suppresses only the archival front;
camera, coordinates, date glyphs, background and all other graphics stay fixed.
Each case must have visible changed pixels, zero protected-graphic changes and
zero changes outside the safe area. Every changed pixel must remain within the
actual projected source stroke/halo corridor; a gap between source parts is
not an allowed shortcut. Original fallback pixels and the sampled work-scene
cut must remain bit-exact. The final CI record, not this policy document, is
the evidence of whether those requirements actually ran and passed.

Software-visible ink does not certify total historical accuracy, NVIDIA output,
full80-second rhythm, mobile video quality, delivery or FINAL promotion.

The preserved V3 helper also returns a constant nested legacy diagnostic hint,
`productionVisual.nativeBoundaryAndReservationsMasked:true`. That hint is not
evidence of the effective V4 source-active mask policy and is not used as an
execution, promotion or quality gate. Read `frontV4.boundaryPolicy`, the V4
`nativeBoundaryGlowPreserved:false` source-active diagnostic and actual A/B
pixel evidence instead. Static-border overdraw is deliberate only within the
real source stroke; graphic reservations still apply.
