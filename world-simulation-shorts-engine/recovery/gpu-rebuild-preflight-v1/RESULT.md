## 시간과 비용

- 유일한 기존 80초 운영 근거는 사용자 보고의 3,600초 제한 도달, 12/12장면·2,400/2,400 카운트다. 실제 완성 MP4, 장면 무결성, 단계별 시간은 확보하지 못했다. 이전 작업은 60분 안에 완성되지 않았다.
- 신규 재제작 완료시간은 **미확정**이다. 다음 작업의 10,800초/180분은 사용할 수 있는 애플리케이션 시간 상한이며, 180분 내 완료 보장이 아니다. 64×96 합성 fixture 시간을 실제 1080×1920 GPU 시간으로 사용하지 않았다.
- 기존 controller는 새 환경에서 10,800초 정책을 검증할 수 있다. 복구 helper가 기존 이미지에 추가됐거나 과거 원격 정책이 바뀌었다고 주장하지 않는다. 과거 3,600초 승인은 보존한다.
- 공식 요금 목록을 기존 Repository Secret으로 읽었다. 첫 GET은 공식 CLI의 JSON Content-Type을 빠뜨려 HTTP415였고, 독립 조회 수집기의 해당 헤더만 수정했다. [다음 무료 CI 39094058722](https://github.com/dimon3898-sys/yeonhwarok-free/actions/runs/39094058722)는 HTTP200이었으나 RTX4080SUPER와 일치하는 공개 단가 행을 확보하지 못했다. 이는 GPU가 전부 없다는 증거가 아니며, 선택 노드 견적은 여전히 **미확인**이다. 원본 실패·성공 조회 기록은 모두 보존했다.
- 따라서 실제 시급·통화·총비용을 숫자로 확정하지 않는다. 공식 자료의 예시 RTX4080 값이나 합성 테스트용 USD 값을 실제 견적으로 사용하지 않았다.

비용 확인식은 **선택 노드 실제 시급 × 배포부터 중지까지의 과금 시간 + 확인된 네트워크·저장소·세금·반올림 비용**이다. 180분 애플리케이션 정책의 입장 검사는 최소 `3 × 실제 시급`의 비용 상한을 요구하지만, 배포 준비·유휴·작업 후 방치 시간까지 자동 제한하지 않는다. Studio timeout은 gCube 과금 종료가 아니며, 공식 문서는 배포 중지 후 포인트 차감이 중단된다고 명시한다.
