# 기존 자료 적용과 남은 데이터 조건

기존 완료 V2의 원본 자료와 출처 검토를 재사용했습니다. 새 역사 좌표·부대 위치·이동 경로를 만들지 않았고 데이터 원본을 변경하지 않았습니다. 상세 바이트 근거는 `DATA_READINESS.json`에 있습니다.

| 자료 | 확인 및 적용 범위 | 제한 |
|---|---|---|
| 공식 지도 기반 전선 8시점 | 1950-12-31, 1951-01-24, 02-28, 04-21, 05-19, 06-24, 11-12, 1953-07-27. 기존 GeoJSON의 실제 바이트와 기록 SHA를 대조했습니다. | 원문에서 구분한 실제 UN 전선의 **근사·부분** 좌표입니다. 원문 투영·측지 기준과 전체 위치 정확도는 인증되지 않았습니다. 완전한 점령 다각형·일별 관측 전선·공격/예정 작전선으로 바꾸지 않습니다. |
| 기존 도식 5단계 | 원래 ROK/UN 보유 핵심 영역이라는 의미와 사건 순서를 유지합니다. | 나머지 육지를 적군 점령지로 추론하지 않습니다. |
| 12장면 연표 | 원래 사건 시각과 지도 기준 시각을 별도로 보존합니다. | 서울 수복·중국군 최초 참전의 정확한 일자 증거는 기존 PARTIAL 판정을 유지합니다. |
| Copernicus DEM | 실제 Float32·EPSG:4326·PixelIsPoint, EGM2008 높이. 약 0.5° 지역 샘플만 지원합니다. | 전 세계 동일 고해상도 지형으로 표시하지 않습니다. NoData·범위 밖은 기존 재질을 사용합니다. |
| GEBCO 2026 | 실제 signed elevation과 약 2°×2° 샘플, 원래 셀 중심 좌표를 유지합니다. | 음수 육지 고도를 바다로 판정하지 않습니다. 같은 프레임의 기존 GIS 바다 coverage가 필요합니다. |
| NASA BMNG | 실제 지역 RGB·EPSG:4326·원래 이미지 정합과 해상도를 유지합니다. | 2004년 8월 합성 지표색이며 현재 관측 영상이 아닙니다. |

기존 2,400프레임의 자료 선택은 도착 구간 60프레임, 도식 영역 1,490프레임, 점령 채우기를 억제한 부분 전선 850프레임입니다. 기존 소스 시간축의 280프레임 전환은 공급된 끝점 상태 사이의 인포그래픽 전환이며, 관측하지 않은 날짜의 전선 좌표를 주장하지 않습니다.

지도 권리는 기존 CMH 지도 작성 주체 검토와 미국 정부 저작물 근거를 재사용했습니다. 책의 모든 사진·제3자 자료를 포괄하여 공개 저작물로 판정하지 않았습니다. ASTRA의 Copernicus·GEBCO·NASA 사용 조건과 출처 표시 요구는 기존 `ESSENTIAL_DATA_REPORT.md` 및 원본 패키지의 라이선스 자료를 그대로 유지합니다. 자료 수집이나 24개 내부 해시·원본 파싱 전체를 반복하지 않았습니다.

현재 백엔드의 검증된 카탈로그는 20개 `GEOMETRY` 기록뿐입니다. `FLOW_PLAN`, `OBJECT_GRAPHIC`, `SCALAR_CONTROL_PLAN`, `NATIONAL_UNIT_SCENE`은 각각 0개입니다. 국가별 실제 군대 표식과 이동, 완전한 양측 점령장, 전투 충돌 위치를 요청하면 해당 기능만 데이터 부족으로 차단합니다. 기존에 검증된 부분 전선과 도식 장면의 사용까지 일괄 차단하지 않습니다.

`data_readiness.py`는 원본 4개 JSON 권위와 실제 사용 객체를 먼저 결속하고 기존 History Admission을 호출합니다. Source ID만 바꾸어 도시 좌표를 군대·이동 계획으로 사용하는 요청, SHA가 다른 payload, 중복된 source ID, 지원하지 않는 요청 필드는 거부합니다. 이 판정은 자료 적합성만 확인하며 GPU 실행·요금·이미지 무결성·영상 품질 승인 권한을 부여하지 않습니다.

별도의 새 `EXTENSION_SOURCES.json`과 `load_effective_catalog()`로 기존 카탈로그를 변경하지 않고 다음 검증 자료를 추가할 수 있게 했습니다. 신규 자료는 현재 0개입니다. 원래 JavaScript canonical 함수를 재사용해 수치 80과 80.0의 표기 차이로 SHA가 달라지는 문제를 방지합니다. 실제 제작은 원본 역사 권위 검사와 원래 Event/Flow/Area 컴파일러 검사를 모두 통과해야 하며, 합성 Fixture는 내부 CPU 검사에서만 허용됩니다. 프롬프트가 카탈로그의 권위를 직접 공급하거나 기존 source ID를 덮어쓸 수 없습니다.
