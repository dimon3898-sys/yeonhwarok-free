# Additive source authority implementation

The new authority is implemented after preserving the first actual 150-frame
software preview under its original source checkpoint. The extension remains
empty: no historical records have been invented to activate optional visuals.

The preserved completion catalog has 20 `GEOMETRY` sources. It must remain
unchanged. Selecting optional scalar or national-unit sources cannot become a
usable general path if those roles can be admitted only by editing that frozen
catalog. Add a new package-owned authority beside the new overnight adapter.

```json
{
  "schema": "WORLD_ENGINE_OVERNIGHT_SOURCE_EXTENSION_V1",
  "parentCatalogSHA256": "434f53f820a0e7c4f28e5d037bd5f8c896c9a71f3c8596f544020dbd9c050036",
  "trustedSources": []
}
```

`EXTENSION_SOURCES.json` must be hashed by the new `OVERNIGHT_FILES.json`, never
accepted from a prompt, upload, public API or unauthenticated configuration.
`data_readiness.load_effective_catalog()` should verify the old manifest-bound
catalog and this new exact package authority, then append non-conflicting records
to a new in-memory catalog. The original parent records, source files and source
hashes remain identical.

The two optional visual contracts use these exact roles:

- `SCALAR_CONTROL_PLAN`: canonical existing scalar plan, bounded original styles
  and any explicit native domain contract.
- `NATIONAL_UNIT_SCENE`: existing national scene, exact per-frame resolved
  anchors/roles, native camera/layout context and actual scene clock.

The existing Event/Flow/Area contract roles `GEOMETRY`, `METRIC`,
`OBJECT_GRAPHIC`, `FLOW_PLAN` and `AREA_INTENT` are also supported. They still go
through the original strict compiler and exact payload/source binding; merely
being present in this new file does not grant renderer or historical approval.

Reject duplicate source IDs, override of a parent record, unknown roles/fields,
invalid review status, non-finite JSON, noncanonical or changed payload hashes,
and production `SYNTHETIC_TEST` records. Explicit internal CPU-test fixtures may
use a synthetic loader option, followed by `compileVisualExtensions` with its
separate internal `allowSynthetic:true`. The public production `--admit` and
Studio gate always keep both synthetic switches false. Isolated synthetic data
in another hemisphere proves the generic plumbing, not historical truth.

The new effective-catalog SHA is the SHA of canonical combined JSON. The
new preview bindings, overnight source-sidecar authority, new browser runtime
configuration and new optional visual consumer all use that same SHA. The
preserved `parentCaptureRequest` and original completion source catalog retain
their exact old identity. `admit_capture_sources` checks original history on a
copy with optional subevents empty, then validates the original unmodified
subevent request with the original Event/Flow/Area compiler and the merged
server-owned catalog. Unknown fields or fake bindings are rejected rather than
emptied and ignored. New browser bindings use the same package-merged authority.

Current real historical extension remains empty. A future real source requires
separate reviewed provenance and license evidence plus the existing exact
payload/compiler and native-composition checks. A national participation date or
flag is not a troop position; partial front polylines are not a complete scalar
ownership field. No historical source may be fabricated to exercise this path.

The new helper and authority have 14 focused tests, including the actual catalog
CLI, exact canonical bytes and an isolated southern/western fixture through the
original scalar compiler/visual consumer. Eight affected original data-readiness
tests also pass. Production rejects that synthetic fixture; no synthetic source
is committed to `EXTENSION_SOURCES.json`. The first output retains its original
source-manifest identity and is not relabelled as later-package output.
