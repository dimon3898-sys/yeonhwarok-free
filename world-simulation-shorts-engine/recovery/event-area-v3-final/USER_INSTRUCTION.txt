PART B — PLANNER / SCENE JSON V1
==================================================

5. 시작 조건

PART A가 완전히 PASS한 경우에만 시작.

목표:

사용자가 자연어로 주제를 입력하면
현재 완성된 World Engine 기능을 조합해
영상 Scene Plan을 자동 생성하는 Planner를 만든다.

예:

"한국전쟁 당시 전선은 어떻게 변했을까?"

→ 사건/위치/시간축 파악
→ 필요한 Camera/Scale 결정
→ Marker/Area/Front/Route/Metric 선택
→ Scene JSON 생성
→ Timeline 구성
→ 기존 Engine으로 렌더

Planner는 Renderer가 아니다.

현재까지 만든 기능을 자동 선택·조합하는 계층이다.

Camera V5

Planner가 이 기능들을 다시 구현하면 FAIL.

==================================================
7. Planner 구조
==================================================

최소 구조:

Natural Language Topic
→ TopicIntent
→ Fact/Event Data
→ Story Beats
→ ScenePlan
→ Scene JSON
→ Existing Engine

Planner 출력은 deterministic한 구조화 데이터여야 한다.

Renderer 내부에 자연어 해석 로직을 넣지 않는다.

==================================================
8. Scene JSON
==================================================

Scene JSON은 최소 다음 범주를 표현할 수 있어야 한다.

metadata
subject
locations
time_range
camera_intent
scale_intent
event_type
beats
geometries
markers
routes
moving_objects
areas
front_lines
metrics
time_steps
text
visual_roles
timing
source_notes

필드가 필요 없는 Scene에서는 생략 가능.

==================================================
9. Beat 구조
==================================================

Planner는 영상을 Beat 단위로 계획한다.

예:

HOOK
→ GEOGRAPHIC_CONTEXT
→ EVENT_APPROACH
→ EVENT_ACTION
→ STATE_CHANGE
→ CONSEQUENCE
→ HOLD

모든 영상이 이 구조를 강제로 사용할 필요는 없다.

주제에 필요한 Beat만 선택한다.

==================================================
10. Feature Selection
==================================================

Planner는 사건 성격에 따라 기능을 선택한다.

예:

이동/물류:
Route + Moving Object

운하/국경/지리:
Line + Metric

쓰나미/재난:
Propagation + Impact Zone

전쟁:
Front Line + Area State + Time Step + 필요시 Route

불필요한 Primitive를 화면에 추가하지 않는다.

==================================================
11. Camera / Scale
==================================================

Planner는 Camera를 직접 계산하지 않는다.

Camera Intent와 대상 Geometry를 기존 Camera/Detail 계층에 전달한다.

Camera V5 Core 수정 금지.

Planner가 특정 화면 좌표를 하드코딩하지 않는다.

==================================================
12. 사실성 정책
==================================================

FACT_BASED_VISUAL_GRADE 유지.

목표는 학술/측량 영상이 아니라
사실 기반의 몰입도 높은 영상이다.

허용:
작은 수치 차이
단순화된 경계
근사 Route
근사 영향권
작은 GIS 오차

금지:
허위 사건
잘못된 국가/위치
실제 진행과 반대되는 표현
큰 규모 왜곡
사실관계를 바꾸는 조작

정확한 자료 확보 때문에 장시간 BLOCK하지 않는다.

==================================================
13. Story / Retention 정책
==================================================

Planner에서 이 부분은 엄격하게 유지한다.

목표:
계속 보게 되는 지도 영상.

검사:

첫 변화가 늦지 않는가
같은 화면이 오래 유지되지 않는가
Camera 변화에 목적이 있는가
정보가 한꺼번에 과다 등장하지 않는가
다음 Beat가 자연스럽게 이어지는가
시선이 어디로 가야 하는지 명확한가
Text가 모바일에서 읽히는가
Hold가 불필요하게 길지 않은가

==================================================
15. Data Source 처리
==================================================

Planner는 Fixture/Data에서 제공된 사실을 우선 사용한다.

실제 Fixture에 필요한 최소 공개 사실은 빠르게 확인 가능.

공식 출처가 쉽게 있으면 사용.
그렇지 않으면 신뢰 가능한 공개 자료 사용.

여러 출처를 끝없이 교차검증하지 않는다.

출처가 불명확하거나 사실관계가 크게 의심될 때만 BLOCK.

==================================================
16. Timing
==================================================

Planner가 각 Beat의 목표 길이를 제안한다.

정확한 초를 고정하지 않는다.

영상 변화량과 정보량을 기준으로 결정.

Dead Time을 피한다.

각 Primitive의 기존 Timeline 계약을 재사용한다.

==================================================

기대:
Route + Moving Object 선택.

B. 쓰나미/재난 주제
기대:
Propagation + Impact 선택.

C. 전쟁/전선 주제
기대:
Front Line + Area State + Time Step 선택.

각 테스트에서 불필요한 기능이 선택되지 않는지 확인.

==================================================
18. 실제 통합 Fixture — 전쟁
==================================================

Planner V1의 실제 통합 테스트는
역사적 전쟁 사건 1개를 사용한다.

조건:

전선/영역 변화가 명확함
시간 단계가 존재함
공개 자료로 핵심 사실 확인이 쉬움
지도 영상으로 이해하기 쉬움

추천 우선 후보:
한국전쟁의 주요 전선 변화.

단 데이터 확보가 불필요하게 오래 걸리면
다른 역사적 전쟁 Fixture로 변경 가능.

실제 Fixture 선택 이유를 기록한다.
