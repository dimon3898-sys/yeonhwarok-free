# Actual historical renderer selection

This task uses the source-checked historical long-runtime consumer. It does not pass the fictional 65422 Scene to a history renderer and does not convert a partial archival line into complete ownership polygons.

The capture adapter in `runtime_adapter.mjs` calls the existing `loadSoftwarePreviewPlan` and `openSoftwarePreviewRuntime` in `universal-overnight-v3/free_preview_runner.mjs`. These functions retain the original native GIS/V5 bridge, ASTRA upload/material factory, Area V3, archival front selector, exact global production clock, completion frontier response, and measured text/marker layout. They run with explicit software-only provenance and no Studio job or GPU admission.

The actual browser composition is selected by the existing server bindings:

1. Completion V2 wrapper `/universal/long_adapter.mjs` invokes the preserved archival V4 adapter through its existing alias.
2. The archival adapter uses `area_native_bridge_v3.mjs` and the original `createMapInfographicRenderer`, then the reference terrain material/ASTRA composition.
3. The existing `selectFrontSnapshot` selects the exact supplied archival geometry by global frame. An active archival line forces `controls.areas=[]`; unobserved opponent ownership is never generated.
4. The existing production Area factory applies the already supported white core/gold halo style to actual supplied geometry. Its completion frontier owner uses supplied observations, not invented intermediate coordinates.
5. Chapter event labels and geometry-date qualifiers remain owned by the preserved glyph/layout passes. Original geographic markers remain read-only.
6. A separate optional director camera edge may use the existing 65422 reference-camera evaluator and native public redraw APIs. It must publish the actual native frame context required by the preserved completion passes.
7. The preserved `longVideoProof.capture(globalFrame)` invokes the actual pipeline draw and WebGL2 `readPixels`, then creates the canvas PNG. No MP4 is read, created, or repeated.

## Capture window

The source plan has twelve contiguous ranges, all sharing the same verified native payload. The new adapter checks this fact before opening a single runtime. It replaces only the in-memory *capture-window declaration* with `[0,2400)`; it does not edit the source document, legacy timeline, source geometries, chapter boundaries, or original Scene files. The old chapter-specific window is retained in provenance. Global indices are passed unchanged to the original event, territory and front consumers.

This separate capture-window declaration contains no chapter-specific event metadata that could falsely label frame 0 as chapter 8. Its hash and all twelve original source ranges are recorded. Source-document hashes are checked before and after capture.

## Relationship to 65422

The shared original native map factory, projection, measured graphics, and reference terrain material are reused. The independently reusable reference-camera evaluator can be selected with a new data-driven presentation profile. This is component reuse, not a claim that the complete 65422 scalar compositor was selected.

The complete 65422 compositor requires a complementary two-faction scalar boundary and its fictional unit positions. The historical 80-second source has partial archival lines, held-core schematic polygons and no sourced national military-unit positions. Its counterfactual scalar fields, roll settings, flags and military positions are therefore not transplanted. Full complementary ownership, historical national-unit placement, arbitrary intermediate front movement and Flow routes remain blocked unless their own source contracts are satisfied.

## Validation boundaries

`assertActualSoftwareFrame` still checks actual ASTRA factory/upload selection, source-before-Area composition, unchanged historical source policy, no fictional Scene usage and `glError=0`. Existing completion and archival assertions check actual selected profile, frame index, archival geometry hash, partial-line-only ownership policy and visible source qualifier. Software results do not authorize or establish NVIDIA rendering or visual quality approval.

This document records source wiring, not successful frame output. Actual frame draw/readPixels evidence must be taken from the capture receipt.
