# Universal input examples

These files are authored test inputs for the new `WORLD_ENGINE_DATA_PROMPT_V1` envelope. They are not pre-rendered scenes and do not themselves prove renderer or video success. The existing native `PLANNER_FACTS_V1` objects remain the inner data contract.

- `FICTIONAL_NAMIBIA.json`: two explicit fictional rectangular area/front states; no real conflict claim.
- `AVIATION_GERMANY.json`: illustrative connection between modern city localities, not an actual airline network or airways.
- `TRADE_CHILE.json`: illustrative cargo connection between modern city localities, not an observed shipping route or measured trade.
- `KOREAN_WAR_MISSING_CONTROL.json`: preserves the source five schematic held cores; exact historical ownership reconstruction must return NEEDS_INPUT.
- `ROMAN_EMPIRE_MISSING_EXTENT.json`: intentionally omits unsupplied ancient dates and boundaries. It must not invent a Roman Empire extent or reuse modern Italy as proof.

`CASE_MANIFEST.json` separates expected contract results from requests. Negative cases are single-field missing, invalid, conflicting and unsupported variants. All cases are pending actual compiler execution. Modern coordinate and frozen native-country extraction proofs are in `../evidence/MODERN_COORDINATE_PROOF.json`. The server-owned historical registry reuses only the previously qualified approximate partial-front scope, as explained by `TRUSTED_EVIDENCE_SCOPE.json`; a caller may not self-approve a historical claim.

All three render candidates last 3 seconds (90 frames) and select only already covered native-terrain regions. Rendering requires successful free CPU and safety gates. No historical completed film,80-second video,paid GPU,FINAL modification or API deployment is authorized.
