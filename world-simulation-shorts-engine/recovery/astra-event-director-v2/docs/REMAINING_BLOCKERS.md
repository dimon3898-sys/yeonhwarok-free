# ASTRA V2 remaining blockers

This is a source/CPU audit. Actual source-review draw/readPixels receipts belong to P5 and must be assessed separately. Neither this document nor the 151-row table approves video quality, a deployed Studio version, NVIDIA execution, or an 80-second production render.

## Historical control and continuous frontier movement

The original five schematic held-cores and eight approximate partial archival fronts remain preserved. A new source-qualified approximate ROK partial front for the evening of 28 June 1950 is registered from Appleman Map I, PDF page 49. It contains three open fragments, not a complete ownership polygon.

The P0 source catalog still supplies no complete two-owner control fields or supported topology/correspondence for the twelve chapter endpoints. `control_contract.py` and `control_bridge.mjs` deliberately return null control endpoints and draw zero historical owner morphs. Partial fronts are not closed to coastlines, and neutral areas are not filled with an inferred enemy complement. Existing scalar and Area engines are preserved; snapshot holds/crossfades do not satisfy continuous occupation expansion.

The minimum evidence needed for a future ownership transition is dated, source-qualified start/end control geometry and a supported correspondence/transition explanation. Additional source digitization must preserve map dates, verified fragments, excluded gaps and total positional uncertainty. There is no basis to declare the required Seoul control-morph sample M2 complete merely because a diagnostic clip exists.

## Requested Local camera

`camera_admission.py` reads original source descriptors and keeps the existing native floor and `LOCAL_NOT_ADMITTED` policy. The current color raster has native 0.005-degree spacing; an enlarged output does not add source detail. Local coastline/source accuracy and complete event geometry also remain unverified. DEM coverage alone cannot certify a detailed surface/coastline view.

`REGIONAL_SOURCE_REVIEW` is an explicit separate diagnostic purpose, not a substitute admitted Local shot. Its camera uses the preserved V5/reference owners with roll zero. P2 CPU checks cover all 2,400 frame states, geometry containment and chapter handoffs; actual native layout, texture support and visible movement still require P5 output. M1's requested Incheon closeup remains blocked where those source/admission conditions are unmet.

## ASTRA texture identity and historical lighting

The new material decorator preserves the old ASTRA factory and privately carries its actual composed `outputTexture` with canvas, owner, frame and bounds identity. It does not overlay a finished image. Actual P5 output must confirm that this material path was selected.

Historical LightV3 is still blocked by `SCALAR_CONTROL_SOURCE_REQUIRED`: no complete trusted historical scalar/ownership field exists. Its draw count remains zero. A valid terrain texture handle is not evidence that historical scalar lighting or moving ownership is connected.

## Historical flags, military markers and audio

Verified geographic city context is available, including Incheon. These points are not evidence of a military unit, landing beach or troop route. Date/role participation gates remain necessary, but do not establish a unit's actual coordinates. The historical marker manifest therefore remains empty. The fictional 65422 positions and modern flags are not copied into the historical Scene.

Reference audio meaning and cue correspondence remain unverified. Audio is explicitly `enabled=false`, `gain=0`, `cues=[]`; conflicting outer-UI defaults are rejected. This is an honest disabled state, not completion of SFX requirements. Existing TTS/BGM/subtitle modules remain out of scope.

## Studio, image and production boundaries

The strict opt-in Event Director request, source/hash registry, normalizer callback and source-review runtime are new independent components. Their existence does not establish support by the current deployed Studio or inclusion in an existing OCI image. Old V1/V2 parsers, existing images, FINAL files, completed jobs and claims are preserved.

No paid GPU, gCube deployment or complete 80-second MP4 is authorized in this task. GPU admission, paid production performance, full-video composition and external Dropbox delivery are not re-certified by this source-review run.

## Feature table interpretation

`FEATURE_STATUS_151.csv` preserves all 151 original IDs and original classifications. The master independently classifies 53 as REQUIRED, 70 as SUPPORTING and 28 as NOT_APPLICABLE. Of the old 53 NOT_WIRED entries, five are REQUIRED. Internal/supporting or unrelated modules are not force-enabled to inflate completion.

Current source binding, CPU validation, actual rendering and visual approval are separate columns/evidence levels. Existing historical frame counts are retained only as past evidence. Root P5 must update actual draw witnesses per feature; a successful import or a clip with no requested ownership effect cannot approve that feature.

Final visual approval remains `USER_REVIEW_REQUIRED`.
