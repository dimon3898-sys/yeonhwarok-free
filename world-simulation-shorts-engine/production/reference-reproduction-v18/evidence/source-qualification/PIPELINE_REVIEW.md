# Independent candidate pipeline review

Status: candidate only. No runtime integration or source acquisition was performed by this review. Existing DSM process was not interrupted. Acquisition authenticity remains pending.

## Fixed for future runs

- Optical and DSM success-only reuse could retain a coarser or different-source decode after plan changes. All three acquisition helpers now call a fail-closed receipt check binding exact requested shape, URL, CRS, decoded affine grid, NPZ hash and declared primary-array hashes. Optical and DSM additionally verify stored invalid/valid mask hashes. Existing classification NPZ hash covers its invalid mask; classification decisions use class values.
- RangeFile returned arbitrary cached bytes without verifying stored receipts. A synthetic corrupt cache returned `b'CORRUPT'` before the change. Cache reads now check byte count, range offsets and SHA-256, and reject missing receipts; they never silently repair cache.
- Cache writes now use same-directory temporary files, fsync and atomic replacement. A cross-process advisory lock covers new readers/writers and live on-disk budget calculation. Concurrent-reader synthetic test verifies one download and identical complete bytes for four readers.
- This is cooperative locking. The currently running old DSM process does not honor the new lock. Do not overlap new acquisitions with that process. No active cache was rewritten by this review.
- DSM future metadata explicitly says DECODED_SAMPLE_VALIDITY_ONLY and nativeContributorCompletenessVerified:false. Finite source zero is not necessarily measured terrain; provider flattening/editing may produce it. No DSM is admitted.

## Remaining admission blockers and smallest fixes

1. **Native invalid contributors are not proven complete.** DSM first uses GDAL masked bilinear downsampling, which may normalize over valid contributors; its subsequent coverage reprojection starts from already-downsampled validity. That cannot establish completeness of the original native interpolation footprint. RGB average has an analogous mixed-validity limitation, already described as overview-scale validity. Future qualification must derive a conservative validity/support mask from the actual source overview/native mask and kernel footprint, with unknown contributors invalid, before reprojecting and applying renderer neighborhood erosion. Merely testing finiteness or giving a derived cell a complete neighborhood does not recover missing native contributors. Synthetic raster reproduction could not run in this review's default Python because rasterio is unavailable there; this is a code-path finding, not a claimed measured defect in acquired cells.

2. **Paired classification masks lack an authenticated derivation link.** Atlas collect() hashes whatever `_classification_masks.npz` exists, but does not bind it to the current classification NPZ hash or prove its array values against that parent. `audit_classified_masks.py` writes masks without a per-mask derivation receipt. A stale mask after classification acquisition could pass atlas candidate validation. Before admission, regenerate/check mask pairing against exact pinned source arrays and bind parent hashes, source/target affine grids, nearest sampling convention and array hashes. Test altered or stale paired masks are rejected. Preserve source-grid 40 invalid-known-land cells regardless of atlas downsampling; do not silently apply the 2020 alternative.

3. **Upstream processing evidence is supplemental, not transitively bound.** Per-product manifests bind source URLs/ranges/grid but the detailed prior average/nearest decode, decoded-transform/NPZ evidence and BMNG native crop receipt live in separate files. Per-product resampling NEAREST only describes the final atlas step. Admission needs a hashed derivation DAG or explicitly hashed evidence index binding original source ranges to decoded arrays, paired masks, fixed color mapping, baseline crop and final atlas. Do not interpret candidate schema success as independent upstream reproduction/authenticity.

4. **Georegistration assertions need to be executable at admission.** Actual atlas center sampling uses bounds/shape and assumes axis-aligned geographic AREA grids. Audit pairing uses tile names and integer ratios. Enforce no shear, expected tile edge alignment, actual decoded transform/bounds consistency and mask-grid agreement before sampling. Existing checks/receipts support these assumptions but the atlas builder does not enforce all of them. Point-registered DSM explicitly reprojects to AREA sample centers, which is the correct intended distinction; source validity still needs item1.

5. **Source snapshot and publication are not atomic.** Atlas build iterates mutable input directories, writes arrays/evidence/manifest in place, and its tests read those paths again. A concurrent update may create mixed-generation artifacts or stale test evidence. Use an immutable input inventory and separate output generation directory, validate every file/hash then atomically publish its manifest/index. Current 86-source update must finish before selecting the final evidence hashes. The tests' hardcoded40/seven-tile expectations are a checkpoint assertion, not generic qualification logic.

6. **Runtime opt-in must remain blocked.** Keep baseline for known water and unknown distinctly; invalid known-land remains unresolved even if baseline visually fills it. Keep DSM disabled until native/overview validity semantics and full runtime derivative support are bound. Smallest safe optical path remains two CPU-composed geographic RGB layers with explicit provenance, all viewport+gutter checks and qualified LOD schedule, separate from strict legacy source selection. Add a truthful mixed-source material treatment, not BAKED_RELIEF for optical. Candidate tests and 1x coverage do not certify seams/clouds/shoreline quality or safe screen-space transition appearance.
