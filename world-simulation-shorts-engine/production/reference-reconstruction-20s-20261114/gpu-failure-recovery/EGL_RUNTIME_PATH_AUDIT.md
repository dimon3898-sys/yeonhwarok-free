## Actual formal process path

The published entrypoint is generated by `release-guard/package_delta.py`: cold-start bootstrap verifies startup/runtime sources and delegates to the preserved HTTPS supervisor. Its `spawn_latest` replaces the Studio server command with cold-start worker, at UID1000. The supervisor separately launches `/opt/world-engine-storage-fix/launch.py`.

Legacy child: `startup._checks` → private UID bootstrap → `gpu_launcher.admit_gpu` → allocation/limits → `prepare_graphics_runtime` → `env.update(updates)` → legacy graphics probe. This helper call is conditional on reaching that stage and successfully loading fixed NVIDIA driver symbols. The original failed job does not retain this child's private admission record, so execution of the descriptor-generation branch cannot be asserted.

Studio child: cold-start worker → pinned `serve.py` → NvidiaPresentationBackend → nvidia_worker → lease_supervisor → NVIDIA capture. No helper call or reading of the legacy Admission environment was found in this chain. The safe health payload also omits selectors/graphicsPreparation; it is not an environment handoff.

The first gap is at the sibling-process boundary, before Controller. The second gap is its selector allowlist. Adding two allowlist names alone cannot carry values that never entered the Controller environment.

## Existing security boundary

The helper uses fixed descriptor roots and canonical containment, bounded JSON format/size, NVIDIA library basename restrictions, trusted absolute library directories and fixed SONAME/driver-entrypoint loading. The runtime filter itself is only a name filter. A synthetic outside-root `VK_ICD_FILENAMES` value survived it in the new investigation; no production path was accessed and no new permission was added. An eventual repair must preserve descriptor validation at the actual crossing point, rather than broadly forwarding arbitrary strings.
