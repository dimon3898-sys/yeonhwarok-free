4. generation3 이후 코드 수정이 있으면 최신 전체 코드·git status·base HEAD·diff·미추적 파일 명세·현재 CHECKPOINT·기존 CPU 결과와 각 시험 소스 해시를 추가한다. 단순 결과 요약 대신 실행 명령·로그·종료코드·검사 대상 SHA256을 포함한다. 과거 GitHub 게시 실패 원문도 포함하되 토큰/비밀번호는 제외한다.
5. 원본 파일별 크기와 SHA256, 묶음별 SHA256, 보존된 경로/alias 전체를 기록한다. 전송 제한을 피하려면 독립적으로 열 수 있는 150MB 이하 ZIP 묶음(DOT_PAYLOAD_001.zip 등)으로 나누고 각 ZIP을 다시 열어 바이트와 해시를 확인한다. 거대한 단일 파일은 조각 해시와 재결합 순서를 명세에 기록한다.
6. 같은 계정에서 다운로드할 수 있는 파일로 올리고, 각 파일의 다운로드 링크/파일 ID·크기·SHA256과 전체 전송 명세를 제공한다. 업로드 완료 응답만으로 회수 검증 PASS를 선언하지 않는다. Work가 다시 받아 원본과 대조할 때까지 Dot 로컬 파일을 삭제하지 않는다.
