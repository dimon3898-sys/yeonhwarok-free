# WORLD ENGINE 80초 제작안 — 인천상륙작전

**상태: 제작 설계·자료 준비본. 실제 80초 MP4와 Studio 제출용 JSON은 아직 생성하지 않았다.**

앞선 80초 제작 요청과 최근 한국전쟁 샘플 요청을 합친 잠정안이다. 이번 메시지에서 주제·길이를 새로 확정받았다고 기록하지 않는다. 기존 10초 성공본, 라벨·지도·기록기와 완료된 검증은 재사용한다.

## 영상의 한 문장

**전선은 남쪽인데, 왜 인천에 상륙했을까?**

남쪽의 위기 → 인천을 고른 이유 → 상륙의 난관 → 9월 15일 상륙 → 16일 남쪽 반격 → 28일 서울 수복. 전쟁 전체를 80초에 욱여넣지 않고 한 번의 반전을 설명한다.

9월 15일 상륙과 16일 낙동강 전선 반격은 국가기록원과 호주 보훈부 자료를 대조했다. 28일 서울 수복은 호주 보훈부 연표로 확인했다. 조수·항로 제약은 미 해군 역사 자료를 사용한다. 인천과 서울의 전략적 관계는 Appleman의 미 육군 원문을 재수록한 학술기관 페이지에서 확인했다. 날짜 확인은 그 날짜의 점령면·부대 위치 확보와 별개다.

## 80초 구성

| 시간 | 전달할 내용 | 화면 연출안 |
|---|---|---|
| 0–4초 | 왜 인천이었을까? | 한반도 전체에서 부산과 인천의 위치만 차례로 강조한다. |
| 4–11초 | 낙동강까지 밀린 전선 | 남동부로 천천히 이동. 현대 국경이나 임의의 점령 색은 넣지 않는다. |
| 11–18초 | 반격을 준비하다 | 부산 지명과 사건 문구를 고정해 읽을 시간을 준다. |
| 18–25초 | 목표는 인천 | 지도를 북쪽으로 이동하고 인천 핀을 드러낸다. 연결선은 이동 항로로 쓰지 않는다. |
| 25–32초 | 서울로 향하는 길목 | 인천·서울 두 지명을 같은 화면에 놓고 번갈아 강조한다. |
| 32–39초 | 쉽지 않은 상륙 | 인천 지역 화면을 유지. ‘큰 조수 차’, ‘좁은 항로’를 순서대로 표시한다. 항만 세부 지도는 사용하지 않는다. |
| 39–46초 | 9월 15일 · 상륙 | 인천 핀에 한 번 강조 효과. 상륙 지점·함선 항로·점령면은 자료 없이 만들지 않는다. |
| 46–53초 | 9월 16일 · 남쪽도 반격 | 카메라를 남동부로 이동. 인천 강조를 해제한 뒤 남쪽 사건 표식을 표시한다. |
| 53–60초 | 두 반격이 맞물리다 | 한반도 화면으로 복귀. 두 사건 카드를 순서대로 강조한다. 정확한 부대 이동 궤적으로 표시하지 않는다. |
| 60–68초 | 9월 28일 · 서울 수복 | 서울을 확대하고 날짜와 지명을 마지막 3초간 고정한다. |
| 68–74초 | 함께 이룬 반전 | 인천·부산·서울 세 지명을 전체 지도에서 순서대로 회고한다. |
| 74–80초 | 하지만 전쟁은 계속됐다 | 서울에서 한반도 전체로 천천히 빠진 뒤 종료. 정전·통일이 이뤄진 것처럼 색을 채우지 않는다. |

## 낭독 대본

0–4초\n전선은 남쪽인데, 왜 인천에 상륙했을까요?

4–11초\n1950년 여름. 국군과 유엔군은 낙동강 일대까지 밀려났습니다.

11–18초\n남쪽에서 방어전을 이어가는 동안, 반격을 위한 상륙작전이 준비됐습니다.

18–25초\n그런데 상륙 목표는 남쪽 전선에서 떨어진 인천이었습니다.

25–32초\n인천에서 서울로 진격해, 북한군의 후방을 압박하려는 작전이었죠.

32–39초\n하지만 조수 간만의 차가 크고, 접근 항로도 좁았습니다.

39–46초\n9월 15일, 인천상륙작전이 시작됩니다. 후방에 새로운 전선이 열린 겁니다.

46–53초\n다음 날, 낙동강 전선에서도 반격이 시작됩니다.

53–60초\n상륙부대는 서울로, 남쪽의 국군과 유엔군은 북쪽으로 진격했습니다.

60–68초\n9월 28일, 서울을 되찾습니다. 남쪽으로 밀리던 전쟁의 흐름이 뒤집힌 겁니다.

68–74초\n인천의 상륙과 낙동강의 반격. 두 작전이 맞물려 전세를 바꿨습니다.

74–80초\n서울은 되찾았지만, 전쟁이 끝난 것은 아니었습니다.

이는 낭독 시간 배정안이다. 음성은 아직 생성하거나 녹음하지 않았으며 실제 음절 길이·호흡·최종 오디오 길이를 검증하지 않았다. 숫자는 낭독 때 한국어 발음으로 읽는다.

## 가독성과 리듬

- 첫 4초에 질문을 제시하고 6~8초마다 새로운 정보로 넘어간다.
- 평소 화면 지명은 최대 2개. 마지막 정리에서만 3개를 순서대로 강조한다.
- 날짜·제목 위치를 고정하고 카메라 이동 뒤 최소 2초는 읽을 시간을 둔다.
- 핀·지명·줌·색 강조·효과음은 사건 이해에 필요한 곳에서 선택한다. 구현된 효과를 전부 동시에 켜는 구성이 아니다.
- 서사상 이동 방향 설명과 실제 부대 이동 항로를 구분한다. 정확한 전선처럼 보이는 임의의 면·경로·국기는 넣지 않는다.
- 현재 지형을 배경으로 쓰더라도 현대 군사분계선·항만·해안이 1950년의 모습인 것처럼 표시하지 않는다. 항만 세부 확대는 입장 조건 충족 전 차단한다.

| 기능 | 확인된 상태 | 이번 제작 적용 |
|---|---|---|
| 지도·도시 핀·라벨·지역 확대 | 기존 구현과 10초 CPU 출력 증거 있음 | 인천·서울·부산 좌표를 기존 고정 자료에서 추출. 새 장면 배치 검증은 남음 |
| REFERENCE_FOCUS_V2 | 신규 10초·300프레임 CPU 영상 완료 | 현재 설정 이미지에는 미포함. 기존 PASS 재실행 금지 |
| 효과음·MP4 합성 | 기존 PCM/FFmpeg 검증 있음 | 큐 계획만 작성. 음성·효과음 파일 미생성 |
| 부분 역사 전선 8개 | 1950년 12월 말~1953년 자료 | 이번 1950년 9월 영상에 날짜를 바꿔 쓰지 않음 |
| 양측 점령면·연속 전선 이동 | 필요한 역사 통제 자료 미확보 | 차단. 임의 보완 금지 |
| 80초 기존 V3/V4 | 별도 장기 제작 경로 존재 | 최신 10초 스타일과 자동 통합됐다는 증거 없음 |
| 현재 Studio 제출 | 코드상 6초·10초 허용 | 80초 JSON 직접 제출 금지. 10초 8구간 분할 계획 작성 |

8구간 분할은 편집 설계이며 각 구간의 실행 JSON·카메라 경계·이미지 결합은 아직 컴파일하지 않았다. STORYBOARD_80S.json은 의도적으로 Studio 입력 스키마를 사용하지 않는다. 화면의 파일 선택란에 올리지 않는다.

## 인수·저장 기록

11월 5일 gCube 공식 답변에 따라 삭제된 private 파일·stdout/stderr 회수는 종료했다. 기존 기록기 연결과 CPU 실패·정체 검증, Dropbox 연결 도구의 구조화된 파일 왕복 증거는 재사용했다. **실제 gCube 마운트에서 생성된 파일의 외부 회수는 아직 별도 증거가 없다.**

이를 확인하려고 GPU를 따로 켜지 않는다. 이후 한 번의 별도 승인된 실행에 저장 확인을 포함하고, 첫 체크포인트의 외부 회수에 실패하면 렌더를 계속하거나 재시도하지 않는다. 실제 마운트 절대경로를 추정하지 않고 기존 사전검사가 허용한 export-root를 사용한다.

## 진행 게이트

1. 첫 신규 10초 입력에 실제 지도 자료·카메라·라벨을 연결하고 기존 검증기로 입장 가능 여부를 확인한다. 새 입력만 검사하며 기존 PASS를 반복하지 않는다.
2. 필요한 역사 통제 자료가 없는 효과는 차단 상태를 유지한다. 효과 지원을 위해 자료를 꾸며 넣지 않는다.
3. 새 입력이 통과한 뒤 8구간 카메라·자막·사건 시간의 경계를 연결한다. 단순 반복·기존 성공본 복제로 80초를 만들지 않는다.
4. 실제 게시 승인 범위와 소스 고정 조건을 충족한 뒤에만 신규 이미지 빌드·게시·설정을 진행한다.
5. 비용·시간·재시도 상한을 포함한 별도 GPU 승인을 받고, 그 실행 안에서 저장 기록 회수를 먼저 확인한다.
6. 완료된 구간만 기존 합성·효과음 도구로 합치고 전체 디코딩과 휴대폰 가독성을 확인한다.
