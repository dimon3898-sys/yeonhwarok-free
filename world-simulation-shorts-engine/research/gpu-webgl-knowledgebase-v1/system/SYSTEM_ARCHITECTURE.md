# WORLD ENGINE 실제 실행 구조와 증거 경계

기준 소스: `296402e71257c7847d0045215ca0cdaf3dd700d2` (`recovery/webgl-surface-restore-20261101`). 아래 연결은 고정 커밋의 코드를 읽어 확인했다. 코드의 존재와 실제 실패 컨테이너의 실행 설정은 구분한다. 기존 PASS 재실행, 코드 수정, GPU, 빌드·게시는 수행하지 않았다.

## 판단에 필요한 핵심 사실

- 최신 실패 `studio-7d7a08be1d09817c903f41484bce3f33`의 안전 진단은 **`UP2_WEBGL2_REQUIRED` / `PAGE_EVALUATE_FIRST_NATIVE_DRAW` / 0프레임 / cleanupVerified=true**다. [원문](../evidence/latest-job/CAPTURE_DIAGNOSTIC.json), [수집 기록](../evidence/latest-job/INTAKE.json). SHA256: `0f61c08da02b98fba68f08f9964c416a3d0d9adf9553e6113fcfc1e75df8baed`.

[S10 · dependency_facts; preflight](https://github.com/dimon3898-sys/yeonhwarok-free/blob/296402e71257c7847d0045215ca0cdaf3dd700d2/world-simulation-shorts-engine/recovery/codex-to-gcube-handoff-v1/controller/nvidia_backend.py#L86-L204).

## 이 연구가 제거한 혼동

입력 사전검사·CPU 300프레임 PASS, source integrity PASS, startup health PASS는 각각 유효한 범위를 유지한다. 최신 null-context 실패가 이 PASS들을 소급 무효화하지 않는다. 최신 실패에서 첫 프레임, 라벨 품질, FFmpeg, MP4 저장은 미실행이다. 따라서 라벨·입력·지역 PNG·FFmpeg를 다시 손보거나 기존 PASS를 반복할 근거가 없다. 다음 판단은 **실패 당시의 실제 Chromium/GPU 실행 환경 차이**에 집중해야 한다.
